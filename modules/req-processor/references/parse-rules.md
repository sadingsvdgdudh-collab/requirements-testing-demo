# 解析与证据

目标是得到保留原文的 Markdown 底稿，供拆分和需求引用。底稿的行号一旦被清单引用就保持稳定；修正转录时重新核对引用并运行检查。

## 按格式处理

| 输入 | 可用方式 | 必须核对 |
| --- | --- | --- |
| Markdown | 直接读取并保留内容 | 链接、表格、引用图片是否完整 |
| DOCX | 当前环境的文档读取/转换工具 | 表格合并单元格、批注、文本框、附图是否遗漏 |
| 文本 PDF | 当前环境的 PDF 提取与页面渲染能力 | 阅读顺序、跨页段落、表格和图文关系 |
| 扫描 PDF、图片 | 当前环境的视觉读取或 OCR | 逐页对照；辨认不出的文字保留为未确认项 |
| XLSX | 当前环境的电子表格读取能力 | 工作表、表头、隐藏行列、公式显示值与备注的业务含义 |

DOCX、PDF和截图的确定性转录由包内document-parser提供，OCR及PDF渲染使用本地运行环境。按[解析说明](../../document-parser/instructions.md)执行并视觉核对，保存解析核对.json。若环境缺少能力，报告未解析文件或页；不得仅依据OCR断定金额、限值和状态名称。解析不等于语义需求提取。

## 底稿内容

保留标题层级、段落、列表、表格字段、数字、单位、条件和例外。保存原文件，并标记底稿段落来自哪一页、哪张表或哪张图；对没有页码的 Markdown 使用真实行号。翻译、归纳和规则解释放到需求规范，不改写拆分所用底稿。

业务五要素是业务背景、输入、流程、输出、约束。它们帮助发现缺口，不是删除内容的门槛。例如“价格不能为负”即使没有完整流程，也是一条应保留的约束。

文字不清、公式无法重算、表格顺序不明或来源相互矛盾时记录具体位置和现象。关键条件未知时产生待澄清问题；P0 是否阻塞按 [数据契约](data-contract.md) 判定。

## 图片

将模块需要的图片复制到模块目录下的 `images/`，名称和标题保留，必要的重名处理用可追溯名称并记录原名。采用 Markdown 图片语法，目标使用模块相对路径，例如 `images/price-rule.png`，替代文本保留图片标题。不要把远程图片当作已归档的本地证据。

`REQ清单.json` 顶层 `images` 为每张图记录 `path`、`description`、`transcription`；需求的 `source.images` 引用这些路径。转录不清楚时在 `transcription` 写明“文字不清，待核对”及具体区域，不能臆测。磁盘 `images/` 中每个图片文件都须登记，登记路径也须存在。

## 解析检查

执行 `check_parse.py --md 模块/解析.md` 检查可机器识别的 Markdown 和本地图片引用问题。检查通过不证明转录语义正确；复杂表格、扫描件仍需页面对照。发现空文件、缺图或残留解析标记时修复来源，不填入假文字。

保留检查发现和人工核对范围供后续拆分报告使用。
