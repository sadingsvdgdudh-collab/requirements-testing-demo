# 编号与变更

所有编号在项目内稳定、唯一，不能以当前文件顺序重新编号。模块缩写由拆分清单登记，使用 2–4 位大写字母，例如 `PRO`。相同缩写不能分配给不同模块。

| 对象 | 格式 | 示例 |
| --- | --- | --- |
| 需求 | `REQ_{模块缩写}_{正整数序号}`，序号至少3位 | `REQ_PRO_001` |
| 验收标准 | `AC_{模块缩写}_{所属REQ序号}_{正整数子序号}`，子序号至少2位 | `AC_PRO_001_01` |
| 用例 | `TC_{模块缩写}_{正整数序号}`，序号至少3位 | `TC_PRO_001` |
| 待澄清问题 | `Q_{模块缩写}_{正整数序号}`，序号至少3位 | `Q_PRO_001` |

序号从 `001` 开始；超出三位时自然扩展。AC 中的需求序号须对应所属 REQ。单条用例可以关联多条 REQ 及其 AC，但不复用编号。

修正文案、补充来源或回答澄清问题而不改变业务含义时保留编号。同一业务规则/测试意图的参数修订（例如上限20→30）可以保留REQ/AC/TP/TC稳定编号，但须保存旧快照、明确更新说明，并对受影响测试点/用例声明same_test_intent=true；不能因此沿用旧评审。规则或测试意图换成另一项时新增编号，旧需求设deprecated或归档旧点/用例，保留理由与来源；废弃、删除编号不交给新对象。见[变更说明](../../change-manager/instructions.md)。

初次整理或增量变更时先读取已有清单和用例，确认当前最大编号与废弃记录。新增对象递增编号；跨模块引用使用完整编号，不缩写为仅数字。

状态、来源和关联字段由 [data-contract.md](data-contract.md) 定义。编号稳定服务于追溯，不表示需求已确认或用例已执行。
