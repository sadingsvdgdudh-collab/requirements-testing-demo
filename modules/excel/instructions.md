# 通用Excel

用户可以只调用此模块：创建多工作表、按明确范围编辑模板、重算公式、检查/统计表格、导入导出CSV/TSV、生成可编辑范围绑定图表。
需求测试流程仍使用原13列用例模块；这里处理一般表格，不替换REQ/测试点/用例验证器。

1. 先确定业务数据、计算口径、输入/输出范围与现有模板。复杂统计口径必须来自用户或明确证据，脚本不猜测。
2. inspect只读检查原文件。编辑前查看源表相关值/公式和已有样式，按模板修改。已有不相关错误仅报告。
3. 根据[Excel contract](references/excel-contract.md)写JSON spec。派生计算写公式，金额/百分比/日期保留真实类型。缺失输入不是0。
4. 使用工作区依赖的Python、Node和@oai/artifact-tool。设置QA_NODE_EXECUTABLE、QA_NODE_MODULES，或在scripts/runtime.json放本机配置；不要把个人绝对路径写进分发包。只读可用openpyxl，所有XLSX作者使用Artifact Tool。
   本模块没有写入回退：工作区缺Node或@oai/artifact-tool时，直接报告"通用Excel能力在本环境不可用"并停止本轮，不安装依赖、不下载、也不改用用例模块的xlsx_fallback（它只覆盖13列用例工作簿）。只读检查仍可用openpyxl完成。
5. 第一次作者前，遵循当前Spreadsheets技能的操作标记要求。标记工具由运行环境提供，本模块不重复调用或假造标记。
6. 创建/编辑时使用QA_XLSX_PREVIEW_DIR保存预览，编辑先渲染源视图，生成后看每个新sheet或受影响视图。spec.preview_ranges可以限制预览范围。修复截断、重叠、乱码和空图。
7. 按实际值检查关键公式和改变输入后的结果，用checks核对独立期望。脚本重算、保存、再读缓存并扫描错误；不支持计算或模板保真失败时拒绝交付。核验不等于所有Excel客户端验证。

默认另存新文件，不允许覆盖原件。已有派生目标需显式--replace-output；这是用户授权覆盖派生文件时才用的选项。
宏、透视、外部链接、复杂对象及无法保真的原模板特性会明确拒绝，不静默降级。遇到拒绝，可在原应用另存清理后的副本，或把可处理数据导入新工作簿；不得擅自丢弃特性。
运行失败报告明确位置，不用改预期结果绕过检查。分析报告仅描述数据和实际公式问题，不自行解释为业务结论。
