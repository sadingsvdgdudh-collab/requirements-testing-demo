# 需求变更演示：名称上限20→30字符

这是合成业务需求的完整文件流程演示，没有执行游戏、后台或测试脚本，也没有伪造测试通过记录。

`completed-project/`保存本次实际运行结果。两个版本原文都在input/；v1需求、测试点、用例、Excel、XMind和待评审报告保存在output/名称长度/history/的旧快照及应用前备份。

共2条REQ、4条测试点和4条用例。两条名称长度边界用例沿用原编号，测试数据由20/21个A改为30/31个A，超限提示改为新原文中的“商品名称最多30个字符”。另两条用例分别检查初始空名称、清空已填写名称；必填规则没有改变，只因原文文件换版而重新核对证据。

TC_LEN_001中的实际结果与execution_records是明确标为未执行的演示导入记录，用于验证设计更新后历史记录不丢失。它们不是v2执行结果。

更新批次中的prepared-before-resolution/保存实际被拒绝发布的未完成草稿，批次根目录保存显式修订后的候选及逐条完成说明。影响报告和应用备份全部保留。旧Excel、XMind、评审及覆盖率结果已移入stale-derived/，当前目录没有冒充新版本有效结果；重新生成待办记录了下一步。

复验命令（在完整技能根目录执行）：

```text
python tests/run_change_example.py
python tests/run_change_example.py --render --output 一个尚不存在的输出目录
```

默认在临时目录复验核心流程并自动清理；`--render`额外实际生成v1 Excel和预览，需要可用的Excel作者运行时。脚本默认拒绝覆盖已有输出目录。第一次生成工作簿后应核对preview-v1/create.png，确认没有裁切或表格错位。本次实际核对还从已归档Excel读取并渲染了右侧4列，保留为create-right.png；未在桌面Excel中打开验证。
