# 旧资料导入实跑示例

这是按原技能包字段格式编写的演示数据，不是真实项目策划案，也没有执行被测系统。来源字段明确说明没有原始策划案页码；导入底稿只证明本次结构化资料实际写了什么。

三个来源是 `source/旧需求.json`（chapter/modules/requirements结构）、`source/旧测试点.json`（原testpoint-extractor字段）和 `source/旧9列用例.csv`（已有用例表）。

每份资料先默认导入一遍，保留草稿、缺字段报告、原件副本和编号映射，再用明确的映射发布完整资料：

- 旧需求没有状态，默认草稿报告缺少status。`mapping/需求映射.json`明确把本演示规则设为active。
- 旧测试点只有FT类型，没有规范的场景类型与设计方法，默认草稿保留原类型并列出待补字段。`mapping/测试点映射.json`明确指定异常场景与错误推测法。
- 旧9列表缺少AC绑定、场景、方法和自动化字段。默认草稿的验收标准仍为空，不把关联REQ的所有AC填进去。`mapping/用例映射.json`明确绑定两条实际被预期结果检查的AC及两条测试点，自动化保留待定。

三份映射还显式指定旧编号与REQ/AC/TP/TC规范编号的对应关系；首次默认导入和随后明确映射使用同一稳定编号。旧测试点的验收文本含中文逗号，仍按完整文本精确匹配，不拆成半句话。

这些映射是演示者对当前示例的显式核对结果，不能直接套用于其他业务。未写明的业务规则没有自动补写；“实际结果：未执行”始终保留。测试点和用例中的P3原值都保持P3。脚本中的字段补齐只采用这些已经给出的决定，不做新的业务推断。

从技能根目录复验：

```sh
python tests/run_import_example.py
```

脚本默认在本示例下建立新的 `runs/唯一批次/` 项目，避免覆盖已有演示结果。也可通过 `--project-dir` 指定新的空项目目录。包内已跑通的结果保留在 `project/`，其中 `复验结果.json` 和 `复验报告.md`记录草稿缺字段、正式条目数、P3保留以及原文件指纹。

正式资料位于 `project/output/商品管理/`；各次导入草稿与报告位于该模块的 `imports/`。正式校验和REQ/AC关联覆盖通过，只代表资料结构与关联可用，尚未逐条开展业务评审，也不代表游戏或产品测试通过。
